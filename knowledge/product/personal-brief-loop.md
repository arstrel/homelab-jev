# The personal brief loop

The target outcome is a current, source-linked obligation inventory in existing Todoist projects. Gmail contributes evidence; Jev answers bounded interpretation questions; deterministic code applies policy. Daily Inbox Digest explains incoming work and Daily Life Plan selects actions for themed Calendar blocks.

The five-minute collector, automatic pending classification, stable private Drive publication and actual daily-consumer handoff are deployed. A separate create-only Todoist capture pilot is enabled. Its wiring is verified, while useful real capture, representative evaluation and the full reply/waiting/completion loop remain unfinished.

The collector stores complete immutable evidence before processing. The publisher reads current Todoist/Retro context and publishes bounded source-linked judgments; it does not invoke GPT to generate plans. Live Todoist and Calendar remain authoritative. October 23 timer retrieval and October 25 canonical JSON repair/readback establish the narrow handoff acceptance, not complete source coverage or calibrated task quality.

Use the repository's product-requirements progress table for current delivery, linked to dated evidence. See [ownership](ownership.md), [delivery boundary](delivery-boundary.md), [processing cycle](/architecture/processing-cycle.md) and [planner handoff](/architecture/planner-handoff.md).
